<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Git worktree → apply command | Staged or unstaged target edits are maintainer-owned work and cannot be overwritten. |
| Fresh candidate bytes → fixed preset files | Validated candidates may update only changed, declared partitions; partial execution remains a documented possibility. |
| Apply invocations → shared checkout | Concurrent processes can race; this mode is explicitly unsupported and has no serialization guarantee. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-04 | Tampering | Git working-tree target files | high | mitigate | Inspect Git status for every pending write target, including staged and unstaged changes; refuse before mutation and test both states. |
| T-03-05 | Denial of service / Tampering | Sequential writes to changed preset targets | medium | mitigate | Validate and preflight the entire write set before mutation, apply only fixed changed targets, verify resulting bytes, and document path-limited Git rollback; explicitly make no multi-file transaction claim. |
| T-03-06 | Tampering | Concurrent apply invocations | low | accept | Concurrent invocations are unsupported in this local, operator-initiated maintenance workflow; the operator runs one process at a time. CLI/help and runbook tests make the limit visible; no locking or serialization guarantee is claimed. |
| T-03-SC | Tampering | npm installs | high | mitigate | No dependency install is planned; if an install is later proposed, require the package-legitimacy audit and blocking human review for any `[ASSUMED]`/`[SUS]` package. |
