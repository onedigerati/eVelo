<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Explicit snapshot path → command | Selected bytes are treated as untrusted input; identity reporting must not imply semantic correctness. |
| Manifest claims → provenance summary | Manifest values are reviewer-provided claims and must be displayed as such, bound to the calculated source digest. |
| Source contract → future validator | Phase boundaries must remain explicit so the identity command is not mistaken for semantic validation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01 | Tampering | Selected source and manifest | medium | mitigate | Require both explicit paths, hash exact source bytes, compare the declared manifest digest, and report mismatches with a nonzero exit. |
| T-02 | Repudiation | Provenance summary | medium | mitigate | Display the selected manifest's attribution, methodology, scope, period, reviewer/date, and exception count alongside the exact source identity; label manifest values as provenance, not validated claims. |
| T-05 | Elevation of privilege | Repository preset files | low | mitigate | Keep the command read-only and limit its output to stdout; tests assert it does not write to `src/data/presets`. |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs no packages; any future package-manager install requires package-legitimacy review and a blocking human checkpoint for [ASSUMED]/[SUS] packages. |
</threat_model>
